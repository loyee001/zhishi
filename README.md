# 植时 · 个人植物养护

按“清新植物风”设计稿制作的个人植物养护网页，支持本地运行与阿里云部署。使用 Node.js 20 或更新版本，无需安装第三方依赖。

- 阿里云部署入口：[植时](https://f.qdfb.tech/plants/)。入口使用独立的个人登录保护，可在不同设备上管理同一份植物与养护记录。
- 代码仓库：[loyee001/zhishi](https://github.com/loyee001/zhishi)。
- 部署、备份与回退说明：[deploy/README.md](deploy/README.md)。登录凭据、个人数据和上传照片不进入代码仓库。

## 本地启动

进入项目目录后运行：

```bash
npm start
```

打开 [本地植时](http://127.0.0.1:4188)。也可以双击项目内的 `启动植时.command`。保持终端窗口运行；关闭服务可按 Ctrl+C。

如果端口被占用，可使用 `PORT=4189 npm start`，打开终端显示的新地址。本地服务仅监听 `127.0.0.1`；手机本身无法通过电脑的回环地址连接，可使用阿里云部署入口访问。

## 功能

- 今日提醒：浇水、施肥筛选，遗漏的任务会继续保留。
- 植物管理：添加、修改、移除，设置名称和位置，上传自己的照片。
- 默认配图：没有上传照片时，按植物名称自动查找网络植物图片；输入“窗边的龟背竹”等名称时会提取植物名。改名后重新匹配，自己上传的照片始终优先。找不到或暂时断网时显示通用占位图，不影响保存和养护提醒。
- 分别设置浇水与施肥的下一次日期、时间、重复间隔及暂停状态。
- 完成养护：必须手动填写实际浇水或施肥日期，核对预览后确认；下次提醒 = 实际日期 + 该项养护间隔，保留设置的提醒时刻。
- 日期复核：拒绝空白、无效、未来及早于或等于上次同类养护的日期，防止误填或重复记录。补记后若下一次日期已到期，仍保留在待办中。
- 历史记录分别展示实际养护日期和录入时间，既有记录保持兼容。
- 暂不需要：跳到下个周期，保留原来的上次养护日期。
- 稍后提醒：从原计划与当前时间中较晚的一个起，推迟 1 小时、1 天或 3 天。
- 月历显示每项计划的下一次提醒；完成后更新下一次日期。
- 养护记录、数据备份导出、桌面及手机尺寸布局。

只有全新的数据目录才会添加 3 盆示例植物；示例日期和周期不是养护建议，可编辑或移除。首次个人部署使用当前已有数据，包括已删除植物后的状态和保留的历史记录，不用示例数据覆盖。

## 数据保存与备份

本地运行时，植物、上传照片和养护记录保存在项目的 `data/plants.json`。阿里云部署时，它们保存在服务器独立的 `/var/lib/zhishi/plants.json`，不同设备登录后读取同一份数据；更新代码不会覆盖该目录。本地版和云端版是两个独立的数据存储，首次迁移之后不会自动同步。

写入通过临时文件和原子替换完成。刷新浏览器或重启服务不会清空数据。移除植物会停止提醒，但保留它的历史记录。`PLANT_DATA_DIR` 可指定持久化数据目录；配置示例见 [.env.example](.env.example)，程序不会自动加载 `.env` 文件。

在“我的”中导出 JSON，或复制完整数据目录进行备份。恢复数据前应先停止对应服务、备份现有 `plants.json`，再用导出的 JSON 替换该文件并启动服务。线上更新与回退遵循[部署说明](deploy/README.md)，不要用旧备份覆盖更新后的养护记录。

## 提醒的使用范围

网页内弹窗默认开启，不需要浏览器通知权限。前台页面每秒按日期和时刻检查到期事项，待办区分“尚未到提醒时间”和“已到提醒时间”；点击“知道了”不算完成养护，同一标签页会记住已看过的本次提示。正在填写表单时先保留提示，关闭表单后补弹；也可在“我的”中点击“测试网页提醒”。

浏览器系统通知是独立的可选功能，需要在当前设备主动开启和授权。数据每 30 秒同步一次，与服务断开时仍按已读取的计划提醒，连接恢复后才能保存修改。

**本地版和阿里云版都需要保持网页打开、设备运行。** 网页关闭或设备休眠时不会继续提醒；后台计时可能受浏览器节流影响，系统通知受省电、勿扰设置影响，恢复页面后会重新检查到期事项。部署到云端使网页与数据可以跨设备访问，不会自动获得后台推送能力。不包含短信、微信、邮件或远程推送。通知实现参考 [MDN Notifications API](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API)。

## 自动配图与来源

自动配图按配置使用 Wikipedia / Wikimedia 或 iNaturalist 的公开接口。默认图源为 `wikimedia`；当部署网络更适合 iNaturalist 时，设置 `PLANT_PHOTO_PROVIDER=inaturalist`。例如本地运行可使用 `PLANT_PHOTO_PROVIDER=inaturalist npm start`，线上在 `/etc/zhishi.env` 中配置并重启植时服务。两个图源共用已有图片缓存。

程序匹配植物名称并校验图片来源；iNaturalist 匹配还检查植物分类与完整名称，重名而无法确定物种时保留占位图。只接受代码支持的公共领域、CC0、CC BY 或 CC BY-SA 许可，不使用保留全部权利、限制商业使用或禁止演绎的图片。图片出处、作者和许可显示在植物卡片与编辑预览中；具体使用条件以每张图片的原始许可为准。首次匹配需要服务器联网，匹配结果与图片保存在数据目录下的 `plant-photos/`，以后可从缓存读取。

只向图片来源发送用于匹配的植物名称，不发送用户上传照片、摆放位置、养护备注或记录。没有上传照片的旧示例图也会改为按名称匹配，已有养护数据无需迁移。

图片接口与许可说明：[MediaWiki PageImages](https://www.mediawiki.org/wiki/API:Pageimages)、[Imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo)、[iNaturalist API](https://api.inaturalist.org/v1/docs/)、[iNaturalist 图片使用许可](https://help.inaturalist.org/en/support/solutions/articles/151000169918-can-i-use-the-photos-and-sounds-that-are-posted-on-inaturalist-)。

主页装饰图与原示例照片由内置 imagegen 生成，保存在 `dist/assets/`，生成提示词在 `dist/assets/prompts.txt`。植物管理、日期计算和页面提醒无需图片提供方即可运行。

## 验证

```bash
npm run check
npm test
```

测试覆盖跨月/闰年日期计算、完成/推迟/跳过、独立周期、重复请求防护、数据持久化及服务重启，以及配图的来源校验、缓存与故障处理。浏览器实际流程与截图记录在本地 `test-results/`，不提交仓库。生产部署还需验证 HTTPS 登录、子目录资源与 API、数据保留及原有站点健康，详见[部署说明](deploy/README.md)。
